# Agents

Conventions come from `../right-answers` (Makefile as the entry point, Lefthook,
gofumpt and the shared golangci-lint config, Prettier, SHA-pinned actions,
Chicago style). Run `lefthook install` after cloning. This file lists only what
is specific to this repository.

## Protocol

`docs/protocol.md` is the authoritative, clean-room description of the Masso
Link wire protocol. Where a community document disagrees, `docs/protocol.md`
wins. It keeps the manufacturer's "MASSO" spelling in quoted material; all new
prose, UI text, and identifiers write "Masso".

A controller talks to one client at a time, and every discovery broadcast
re-targets every controller that hears it. Keep broadcasts to a minimum and
never run two clients against the same controller (that includes Masso Link).

## Windows-only code

`github.com/tailscale/walk` builds only on Windows. It may be imported only from
`internal/ui/walkui` and `cmd/mink-lasso/gui_windows.go`. Everything else must
build and test on macOS and Linux, taking Windows-specific behavior through
`internal/winutil`, which has non-Windows stubs. That rule is for production
code: a test may keep a `//go:build windows` helper of its own (with a
non-Windows twin) when the platform difference is in what the test can do, such
as how it interrupts a child process. `make lint` runs golangci-lint twice,
natively and with `GOOS=windows`, so both halves are checked.

`cmd/mink-lasso/rsrc_windows_amd64.syso` (icon, version info, and the manifest
that walk requires for Common Controls v6) is generated by `make winres` from
`build/winres.json` and committed so a plain `go build` produces a correct exe.

`internal/ui/walkui` is excluded from `make coverage`, so `make lint`'s
`GOOS=windows` pass only compiles and vets it—nothing checks that a call
actually behaves as expected at runtime. Before changing it, verify the
`github.com/tailscale/walk` symbols you use (names, signatures, behavior)
against the source in the module cache rather than from memory, and check
README.md's "Manual checks" list by hand on Windows afterward.

## Coverage

`make coverage` requires 100% statement coverage of every package except `cmd/*`
(one-line `main` functions) and `internal/ui/walkui` (needs an interactive
Windows desktop). All UI decisions live in `internal/ui/model`, which is fully
tested; the walk binding only paints what the model returns. Packages take their
side effects (clock, filesystem, sockets) through small injectable interfaces so
error paths are testable.

## Process lifecycle

`internal/app` owns flags, config, logging, the single-instance guard, and
wiring the engine, the model, and (on Windows) the GUI together;
`cmd/mink-lasso` is a two-line `main`. `Engine.Events()` must be drained until
it closes, or `Engine.Run` never returns—`internal/app`'s event-forwarding
goroutine and `walkui`'s event pump both keep draining after their own consumer
(GUI or headless mode) has stopped, so a closed window or a canceled context
never deadlocks shutdown. Preserve this if you touch either goroutine.

## Versioning

Versions follow [gitcalver](https://gitcalver.org/) (`YYYYMMDD.N`) and are
computed by the Makefile from git history; releases are tagged `v0.YYYYMMDD.N`.
There is nothing to bump.

## Simulator and integration tests

`make sim` runs a fake controller (`internal/masso/sim`) for development on any
OS; `make run RUN_ARGS=...` runs the app headless against it. `make integration`
runs `internal/integration` (build tag `integration`) against a real controller,
by hand from a Windows PC on its LAN (there is no CI job: the controller is
powered down between sessions); every test skips unless `MINK_LASSO_SERIAL` is
set, and the upload/E2E tests additionally skip while the machine is running
unless `MINK_LASSO_ALLOW_RUNNING=1`. The E2E test needs the built exe, found via
`MINK_LASSO_EXE` (set by the `integration` Makefile target); it skips itself if
unset. Test files are named `MLTEST*.NC` so they are easy to find and delete on
the controller.
